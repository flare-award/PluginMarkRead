# MarkRead

Кооперативные подтверждения прочтения (read receipts) для личных сообщений Discord в [Vencord](https://vencord.dev).
Отправитель видит рядом со временем своего сообщения одну галочку — «отправлено», и две — «прочитано».
Две галочки появляются только после того, как клиент получателя **действительно показал сообщение** и подтвердил это подписью через собственный relay-сервер.

> Discord не предоставляет API состояния прочтения. Любой плагин, который рисует «прочитано» без участия второго клиента, обманывает вас.
> MarkRead не угадывает: доставка, онлайн-статус, открытый канал и ответ — не доказательства прочтения.

## Как это работает

1. Оба участника устанавливают MarkRead, включают обмен подтверждениями и указывают **один и тот же** relay (свой сервер, см. [`server/`](server/README.md)).
2. Клиент получателя следит за сообщениями через `IntersectionObserver`. Подтверждение создаётся, только если сообщение:
   - видно в окне не меньше заданного времени (по умолчанию 1,5 с),
   - находится в выбранном канале,
   - окно Discord активно и видимо, нет модального окна,
   - видно хотя бы частично (минимум 96 px высоты или вся строка для коротких сообщений).
3. Клиент подписывает подтверждение ключом ECDSA P-256 (создаётся локально, хранится в IndexedDB) и отправляет на relay по WSS.
4. Relay проверяет подпись, авторизацию, ограничения частоты и пересылает подтверждение автору сообщения. Если автор офлайн — подтверждение ждёт во входящих relay (ограниченное время).
5. Клиент автора ещё раз проверяет подпись, отправителя, канал, сообщение и версию сообщения. Только после этого загораются две галочки.

Подтверждение привязано к версии сообщения: если сообщение отредактировали после прочтения, показывается «прочитано до редактирования», а новое содержимое требует нового подтверждения.

## Возможности

- ✅ / ✅✅ рядом с временем **своих** сообщений в 1:1 DM (cozy, compact и сгруппированные сообщения).
- Настоящая криптографическая проверка: подпись ECDSA P-256, TOFU-пиннинг ключей собеседника, отпечатки в настройках.
- Защита от дублей: журнал отправленных подтверждений, дедупликация по `receiptId` на клиенте и relay, привязка к версии сообщения.
- Удаление и редактирование сообщений учитываются; подтверждения удалённых сообщений вычищаются.
- Настройки: включение обмена, отправка своих подтверждений (по умолчанию выключена), URL relay, время показа, размер и цвет индикатора, opt-out для конкретного DM.
- Полностью локальное хранение: IndexedDB через `DataStore` Vencord. Никакой телеметрии, аналитики и содержимого сообщений.
- Свой relay на Node.js с авторизацией по challenge-response, проверкой подписей, лимитами, офлайн-очередью и HTTPS/WSS-документацией.
- Подробная русская документация: установка на Windows 10, развёртывание сервера, модель угроз и ограничения.

## Быстрый старт

1. **Relay.** Разверните сервер по инструкции [`docs/server.md`](docs/server.md) (Node.js 20+, TLS обязателен; для локальных тестов допускается `ws://localhost`).
2. **Плагин.** Соберите Vencord с папкой `markRead` в `src/userplugins` по инструкции [`docs/install-windows.md`](docs/install-windows.md).
3. Откройте настройки MarkRead в Discord:
   - включите **Receipt exchange**;
   - укажите `wss://ваш-relay/ws`;
   - при желании включите **Share read receipts** (без этого вы получаете подтверждения, но не отправляете свои);
   - нажмите **Reconnect now** и убедитесь, что статус «Connected».
4. Собеседник делает то же самое с тем же relay. После этого под его сообщениями появляются ✅, а после реального прочтения — ✅✅.

Проверка работоспособности: `npm test` в корне (клиентские тесты), `npm --prefix server test` (тесты relay).

## Честные ограничения

- **Нужны обе стороны.** Если у собеседника нет MarkRead (или он не подключён к тому же relay), вы увидите только ✅. Это не баг, а отсутствие данных.
- **Нужен свой сервер.** Плагин не использует платные API; relay вы поднимаете сами. WSS обязателен, кроме локальной разработки.
- **Только 1:1 DM.** Групповые DM и серверные каналы не поддерживаются в v1.
- **Только десктоп.** Vencord работает в Discord Desktop (Windows/macOS/Linux) и в браузере; мобильный клиент не поддерживается.
- **Нет подтверждения доставки.** MarkRead показывает прочтение, а не доставку: одна галочка означает «отправлено», а не «доставлено на устройство».
- **Relay видит метаданные.** Discord ID, случайный device id, IP-адрес и идентификаторы каналов/сообщений подтверждений. Содержимое сообщений не передаётся.
- **Доверие к собеседнику.** Подтверждение доказывает, что клиент собеседника показал сообщение. Вредоносный клиент может врать; TOFU-пиннинг защищает от подмены ключа третьей стороной, но не от самого собеседника.

Подробнее: [`docs/security.md`](docs/security.md), [`docs/limitations.md`](docs/limitations.md).
