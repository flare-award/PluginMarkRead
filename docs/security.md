# Модель угроз и гарантии

## Что гарантирует MarkRead

1. **Две галочки никогда не рисуются без проверенного подтверждения.** Единственный источник состояния «прочитано» — подписанное сообщение, полученное от собеседника и проверенное по его публичному ключу.
2. **Подтверждение создаётся только при реальном показе.** Учитываются видимость окна, фокус, выбранный канал, отсутствие модального окна, площадь видимой части строки и непрерывное dwell-время. Доставка сообщения, онлайн-статус, открытый канал или ответ не считаются прочтением.
3. **Подпись привязана к конкретному сообщению и его версии.** Поля `from`, `to`, `channelId`, `messageId`, `messageVersion`, `readAt`, `sentAt` входят в каноническую строку подписи. Подменить адресата, канал, сообщение или версию нельзя.
4. **Никаких секретов Discord.** Плагин не читает токены, не использует self-bot, не пишет скрытые сообщения/реакции и не обращается к Discord API для «подтверждения».
5. **Никакой телеметрии.** Нет аналитики, сбора содержимого сообщений, вложений или истории. Удалённые сообщения вычищают связанные подтверждения из локального хранилища.
6. **Осознанное согласие.** По умолчанию обмен и отправка выключены. Пользователь может отключить конкретный DM. Собеседник должен сам установить плагин и включить отправку.

## Что MarkRead не гарантирует

- **Честность собеседника.** Вредоносный клиент может подтвердить сообщение, не показав его. Протокол фиксирует ответственность ключа, но не может доказать, что человек физически смотрел на экран.
- **Достоверность времени.** `readAt` — часы получателя. Клиенты и relay проверяют разумные окна (не более ±10 минут на отправку, 30 дней на приём), но точное время не является доверенным.
- **Защиту от вредоносного relay.** Relay может не доставлять подтверждения, задерживать их или пытаться подставить новый ключ. Пиннинг ключей (TOFU) блокирует подмену уже известного собеседника; при первой встрече доверие устанавливается к тому ключу, который relay отдал первым. Отпечатки можно сверить вне канала.
- **Скрытность метаданных.** Relay видит Discord ID, случайный device id, IP-адрес, идентификаторы каналов и сообщений, время. Это неизбежно для любого серверного решения. Содержимое сообщений не передаётся.

## Криптография

| Компонент | Решение |
| --- | --- |
| Идентичность | ECDSA P-256 (WebCrypto `crypto.subtle`) |
| Приватный ключ | Неизвлекаемый `CryptoKey` в IndexedDB (`markread.identity.v1`); резервный JWK — только если среда не поддерживает неизвлекаемые ключи, с предупреждением в настройках |
| Подпись | SHA-256, формат r‖s (WebCrypto), base64url |
| Канонизация | Детерминированный JSON: сортировка ключей, без пробелов, только safe integers |
| Аутентификация на relay | Challenge-response: сервер выдаёт 32 случайных байта, клиент подписывает `markread-auth-v1\n<userId>\n<deviceId>\n<nonce>` |
| Домены подписи | Разделены префиксами `markread-auth-v1` и `markread-receipt-v1` — подпись авторизации нельзя переиспользовать как подтверждение |
| Пиннинг | TOFU по `Discord ID → публичный ключ`, отпечаток SHA-256 (64 бита, 4 группы) |
| Повторы | `receiptId` (UUID v4), кеш на 24 ч; relay дедуплицирует, клиент игнорирует повторный `receiptId` |

## Модель доверия relay

Relay обязан:

- проверить подпись challenge-response до любых других действий;
- принимать подтверждения только от аутентифицированного пользователя, чей ключ совпадает с зарегистрированным;
- проверять `from` в подписи и временные окна;
- дедуплицировать `receiptId`;
- не хранить содержимое сообщений (его у него нет);
- ограничивать частоту и число соединений.

Relay **не** может:

- подделать подтверждение от имени пользователя, ключ которого уже известен клиенту (нет приватного ключа);
- изменить подписанные поля незаметно;
- прочитать содержимое переписки.

Relay **может**:

- не доставлять подтверждения (denial of service);
- видеть метаданные;
- при первом контакте выдать свой ключ вместо ключа собеседника — именно поэтому отпечатки показываются в настройках и их можно сверить вне канала.

## Приватность по умолчанию

- `exchangeEnabled: false`, `shareReadReceipts: false` — плагин не подключается и ничего не отправляет, пока пользователь явно не включит обмен.
- `showReadTime: false`.
- В настройках перечислены точные категории локальных данных и метаданных relay.
- Кнопки удаления данных требуют подтверждения и удаляют IndexedDB-записи.

## Ограничения безопасности клиента

- Плагин работает в renderer-процессе Discord. Вредоносный плагин или скомпрометированный клиент может обойти любые проверки. MarkRead не является DRM или системой контроля.
- XSS/компрометация Discord-клиента может получить доступ к IndexedDB. При неизвлекаемом ключе — только использовать его для подписи, но не выгрузить.
- При резервном JWK-хранилище ключ извлекаем. Настройки явно предупреждают об этом.

## Отчёт об уязвимости

Не публикуйте эксплойты публично. Свяжитесь с оператором вашего relay и автором форка; при использовании официального репозитория создайте приватный security advisory.
